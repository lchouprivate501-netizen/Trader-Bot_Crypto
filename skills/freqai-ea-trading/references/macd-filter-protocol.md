# 自學習 MACD 假訊號過濾器：驗證協議（事前登記）

本檔與凍結的指標（`tradingview/pine/self_learning_macd.pine`）、參考實作（`scripts/macd_filter_research.py`）在跑任何測試資料之前一起推上 GitHub（見 git 歷史的時間戳）。之後只能新增結果，不能改這裡的期間、門檻與判定後的用法。

這個指標與本專案的 EA 無關：它不下單、不改任何 EA 的參數或風控，只是給使用者在 TradingView 上看的 MACD 指標。

## 要回答的問題

在任意標的、任意時間框架上，經過過濾的 MACD 交叉（主圖上的「多 / 空」標籤）是否比全部 MACD 交叉更好？自我學習（每張圖用自己的結果更新權重）是否比只用固定權重更好？

## 研發期做了什麼（已完成，只用研發資料）

研發資料：BTC、ETH、SOL、BNB、XRP 現貨，15m / 1h / 4h / 1D，2019-01 → 2023-06-30。

1. 量化原始 MACD(12,26,9) 交叉的痛點（見研究報告）。
2. 選定交易模型：交叉收盤進場；出場 = 下一次反向交叉的收盤，或先觸及 1.5×ATR(14) 保護停損（跳空穿過以開盤價成交），最長 300 根；成本來回 0.10%。R = 停損距離。
3. 選定 11 個無單位特徵、線性預測、遞迴最小平方法（RLS，先驗強度 100 筆、不遺忘），門檻「預測淨 R > 0」；這些選擇在研發期前後兩半互相交叉檢驗過。
4. 先驗權重用全部研發資料擬合後凍結：

| 常數 | 方向 | 高週期 MACD-V | 高週期柱 | EMA200 距離 | 100 根動能 | 效率比 | 波動收縮 | 成交量 | MACD-V | RSI |

| 集合 | 標的 | 期間 | 角色 |

時間框架：15m、1h、4h、1D（高週期自動對應 1h、4h、1D、1W），共 13 × 4 = 52 個組合。學習器從每個組合資料的第一根開始依時間順序運行（只用已經出場的交叉學習），評估只計 T 期間進場的交叉。

## 比較的版本

- **原始**：全部 MACD 交叉。
- **自學習（交付版本）**：先驗 ＋ 每張圖 RLS 學習，預測淨 R > 0 才標示。
- **固定**：只用先驗權重，不學習。
- **TradingView 5000 根**：每 5000 根 K 線把學習器重設回先驗（模擬 TradingView 免費方案只載入 5000 根）。

## 通過門檻（P1–P4 全部符合才算「有效」）

只計過濾後訊號 ≥ 10 筆的組合（排除的組合數照實回報）。每個組合同等權重。

1. **P1**：T 上「過濾後平均淨 R − 原始平均淨 R」的平均 > 0，且以組合為單位的 bootstrap 95% 信賴區間下限 > 0。
2. **P2**：T 上 ≥ 70% 的組合「過濾後平均淨 R > 原始平均淨 R」。
3. **P3**：T 上假訊號比例（淨 R ≤ 0 的訊號占比）過濾後低於原始。
4. **P4**：T-hold 上 P1 的平均差 > 0。

另外兩項決定預設設定：

5. **P5 自我學習**：T 上自學習版本的平均淨 R ≥ 固定版本。未通過 → 指標的「啟用自我學習」預設改為關閉，並照實告知。
6. **P6 TradingView 歷史長度**：T 上「TradingView 5000 根」版本的 P1 平均差 > 0。未通過 → 告知使用者需要更長的圖表歷史，指標在少於該歷史時效果不保證。

一律另外回報（不影響判定）：各時間框架的結果、多空分開、每筆風險 1% 的權益報酬與最大回撤、同期買入持有的報酬與最大回撤。

## 判定後怎麼用（事前決定）

- P1–P4 通過：交付指標，告知使用者它在測試期間能有效減少假訊號，以及各時間框架的實際期望值（包括仍為負的情況）。
- 任何一項未通過：照實回報，不在測試資料上調參補救；若要改版，視為新版本、重新事前登記並用新的未看過資料驗證。
