# 合約 EA 驗證協議（事前登記）

本檔在任何合約 EA 回測之前寫好並推上 GitHub（見 git 歷史的時間戳）。之後只能新增結果，不能改這裡的期間、門檻與判定後的用法；若要改，必須寫明原因並把那個 EA 視為新版本、重新驗證。

## 要驗證什麼

合約 EA ＝ 已驗證的現貨 EA 多單規則（參數不變）＋ 新的空單規則 ＋ USDT 永續合約（逐倉、要付或收資金費）。要回答兩件事：每個幣的合約 EA 在從沒調過參的期間是否有效；以及空單是否真的有貢獻（而不只是多單換到合約上）。

研究與調參必須遵守的設計限制：

- **多單**：直接沿用現貨 EA 的凍結參數（`BTCTrendEA`、`ETHRiskOnEA`、`SOLMomentumEA`，commit c526239），不再調整。
- **空單**：與多單對稱的機制——價格在趨勢 EMA 之下並跌破前 N 小時低點時進場、吊燈停損從進場後最低價往上算、趨勢轉多時出場；ETH 的空單只在 BTC 處於空頭（BTC 在其趨勢 EMA 之下）時進場。空單參數只能在研發期 D 研究與調整，每個幣調參的組合總數 ≤ 200。
- **部位**：固定風險，與現貨 EA 相同（停損一次約虧權益的 `risk_per_trade`），名目部位 ≤ 權益的 95%。
- **槓桿**：逐倉。槓桿 ＝ 讓清算價距離 ≥ 2 倍初始停損距離的最大整數，上限 3 倍、至少 1 倍。槓桿只減少佔用的保證金，不放大部位。
- 同一個幣同時只有一個部位（多或空）。

## 共同設定

Binance USDT-M 永續、逐倉、每邊手續費 0.05%（taker；V4 另測 0.10%）、資金費依 Binance 歷史紀錄由 Freqtrade 計算、清算依 Freqtrade 內建的 Binance 槓桿分層、起始 10,000 USDT、Freqtrade 2026.10 + FreqAI（同現貨 EA：purged walk-forward，180 天訓練、30 天重訓）、1h K 線訊號、15m 細節 K 線模擬停損與清算。最大回撤一律用盯市權益（逐小時，含未平倉）。「空單淨損益」＝ 所有空單的 `profit_abs` 加總（已扣手續費與資金費）。

## 通過門檻（全部符合才算「驗證通過」）

**BTC、ETH**

1. V1 總報酬 > 0
2. V1 盯市最大回撤 < 同期買入持有最大回撤的 50%
3. V1 獲利因子（扣費後）≥ 1.3，且交易 ≥ 15 筆
4. V2 報酬 > 0、且 > 同期買入持有報酬，V2 盯市最大回撤 ≤ 30%
5. 空單有貢獻：V1 與 V2 的空單淨損益合計 > 0
6. V4：研發期內 ≥ 75% 的參數擾動版本仍獲利；每邊 0.10% 手續費下研發期仍獲利

**SOL**

1. V3：6 個幣中 ≥ 4 個獲利，且 6 個幣平均報酬 > 0
2. V3：6 個幣平均盯市最大回撤 < 它們買入持有最大回撤平均值的 50%
3. 研發期 SOL 本身獲利因子 ≥ 1.3
4. V2 同 BTC/ETH 第 4 條
5. 空單有貢獻：V2 與 V3（6 個幣）的空單淨損益合計 > 0
6. V4 同 BTC/ETH 第 6 條

## 判定後怎麼用（事前決定）

- **通過的幣**：合約 EA 成為該幣在本專案的主要策略。
- **未通過的幣**：合約 EA 只做影子紀錄、不下單；若該幣的現貨 EA 已通過驗證，該幣的主要策略維持現貨 EA。
- 不論通過與否，都回報與現貨 EA 在相同期間的比較（不影響判定）。

未通過的 EA 照實回報，不在驗證期間上調參補救。
