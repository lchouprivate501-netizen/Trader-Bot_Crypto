# 全網加密貨幣日內篩選器：用法、方法與驗證結果

> 協議（看結果之前寫好並 commit）：[`intraday-screener-protocol.md`](intraday-screener-protocol.md)，含一次協議外修正的補記。
> 程式：`screener/intraday_screener.py`（只用 Python 標準函式庫、只讀公開行情、不需金鑰）。
> 不是投資建議。

## 先講結論

| 你要的 | 做得到嗎 | 證據（Binance 全部 USDT 永續，含已下架；保留期 2026-06-01 → 11-15） |
|---|---|---|
| 流動性高 | **做得到**（硬門檻） | 日成交額中位數與最近 24h 都 ≥ 20M USDT；即時模式另看價差 ≤ 5bp、25k USDT 市價單滑價 ≤ 10bp |
| 波動率高 | **做得到** | 清單前 10 名隔天每 4 小時淨移動 2.03%，合格幣平均 1.57%（+29%）；過去的波動對隔天波動的截面相關約 0.67，研發期與保留期一樣 |
| 不要入場後就盤整 | **只做到一部分** | 門檻把加密貨幣隔天的盤整率從 **49.3% 降到 36.7%**（主要是排除死幣、極低流動性的幣）。但在合格的幣之間，**沒有任何指標能預測哪個幣明天比較不會盤整**：清單前 10 名 37.0%，和其他合格幣一樣 |

**事前登記的判定：未通過**（H1、H2 沒過，H3 過，見下表）。篩選器保留，但它的定位是「挑流動性夠、會動的加密貨幣」，不是「挑不會盤整的幣」。

為什麼消不掉：短線（15 分鐘 K、4 小時視窗）的加密貨幣價格很接近隨機漫步。隨機漫步本身就有 **約 36%** 的 4 小時視窗會被這裡的定義判成盤整；流動性夠的幣實測 36–37%，已經在這個地板上。剩下的盤整是常態，要靠進場後的規則（停損、出場）處理，不是靠選幣。

## 用法

```bash
SK=skills/freqai-ea-trading/screener
python3 $SK/intraday_screener.py scan                          # Binance USDT 永續，今天的觀察清單（前 15 名）
python3 $SK/intraday_screener.py scan --exchange all --top 20  # Binance + Bybit + OKX 合併（同一個幣成交額相加）
python3 $SK/intraday_screener.py scan --exchange bybit         # 所在地連不到 Binance 時
python3 $SK/intraday_screener.py scan --exchange archive       # 交易所 API 全被擋時：Binance 歷史資料庫（到昨天收盤，沒有價差 / 滑價 / 資金費）
python3 $SK/intraday_screener.py now SOL DOGE SUI              # 幾個幣剛剛 4 小時的盤勢 + 目前時段的歷史盤整率
python3 $SK/intraday_screener.py scan --json out.json --html out.html
python3 $SK/intraday_screener.py scan --config my.json         # 覆寫門檻（只寫要改的欄位，例如 {"min_median_qv_usdt": 50000000}）
python3 $SK/intraday_screener.py scan --news --log             # 加新聞催化劑（未驗證、不影響排名）並存紀錄供前向驗證
python3 $SK/news_catalyst.py SOL DOGE                          # 只看幾個幣最近 48 小時的催化劑
```

每天自動跑（AI 讀新聞、分級、寫報告、累積驗證資料）：見 [`screener/prompts/README.md`](../screener/prompts/README.md)。

一次 `scan`（Binance）大約 150–300 次公開 API 請求，已內建限速（Binance 1,500 權重 / 分鐘，官方上限 2,400），約 1–3 分鐘。OKX 的歷史 K 線每次只給 100 根，`--exchange okx` / `all` 會比較慢。

輸出欄位：

| 欄位 | 意思 |
|---|---|
| 分數 | 合格的幣之間的百分位加權（0–100），權重見下 |
| 24h額 | 最近 24 小時成交額（`all` 時為各交易所合計） |
| 日振幅 | 過去 14 天平均 (高−低)/開 |
| 4hER | 4 小時區塊效率比：淨移動 ÷ 走過的路。1 = 一路走，0 = 原地來回；隨機漫步約 0.25 |
| 盤整率 | 過去 14 天 ER < 0.15 的 4 小時區塊比例 |
| VR | 4 小時變異數比（>1 偏趨勢、<1 偏均值回歸） |
| RVOL | 最近 24h 成交額 ÷ 過去 13 天的中位數 |
| 滑價 | 一筆 25k USDT 市價單的平均滑價（bp，買賣取較差的一邊；只有即時模式） |
| 近4h | 剛剛 4 小時的盤勢（單邊↑/↓、偏多/空、收斂、來回洗）。**只是描述，不是預測**（見驗證） |
| 提醒 | 資金費擁擠（≥ 0.05%/期）、成交額暴增（≥ 3 倍，事件盤）、振幅接近上限、和 BTC 相關 ≥ 0.85 |

## 方法

### 1. 硬門檻（不合格就剔除，`config.json`）

| 門檻 | 預設 | 為什麼 |
|---|---|---|
| 日成交額中位數（14 天）、最近 24h 成交額 | ≥ 20M USDT | 執行品質（滑價、能不能進出）。盤整率在 2M 以上就已經平了（見下），20M 是給實際部位的餘裕 |
| 上市天數 | ≥ 15 天 | 新幣資料不夠、波動結構不穩 |
| 穩定幣、黃金代幣、指數合約 | 剔除 | 不是日內波動標的 / 不是單一幣 |
| 股票、ETF、商品、外匯永續 | 剔除 | Binance 2026 年有兩百多個這類合約（AAPL、NVDA、TQQQ、HK0700、XAU、NATGAS…）。三道：`non_crypto.json` 清單（232 個，產生方式寫在檔案裡）、即時模式的 Binance `underlyingType`、14 天備援檢查（週末成交額 < 平日 0.25 倍且振幅 < 0.7 倍） |
| 日振幅（14 天平均） | 3%–25% | 3% 以下幾乎不動；25% 以上停損要放很寬、容易被洗（上限是風險控管，不是因為盤整：盤整率在 3% 以上都差不多） |
| 價差、滑價（即時模式） | ≤ 5bp、25k 市價單 ≤ 10bp | 日內交易的成本 |

### 2. 分數

在合格的幣之間把每個因子排百分位，等權重平均成 0–100。因子在研發期依事前登記的規則選出（對隔天 4 小時淨移動的預測力 t ≥ 2、而且不讓盤整率顯著變差；彼此相關 > 0.9 的只留一個）：

`er4h`（4h 效率比）、`anti_chop`（−盤整率）、`vr4h`、`vr1h`（變異數比）、`er_day`（整天效率比）、`body`（日 K 實體比）、`er4h_3d`（近 3 天 4h ER）、`move4h`（過去 14 天 4h 淨移動 %）、`rvol`（相對成交額）、`expansion`（近 3 天振幅 ÷ 14 天）、`abs_chg`（|24h 漲跌|）。

被排除的：`range` 與 `tr15`（和 `move4h` 相關 0.97，只留一個）、`liquidity`（成交額越大的幣隔天動得越少，IC −0.22）。

### 3. 近 4 小時盤勢與時段

`now` 與清單的「近4h」欄描述剛剛 4 小時（最後 16 根 15 分鐘 K）：ER < 0.15 → 來回洗；ER ≥ 0.35 且振幅不低於平常 → 單邊；振幅不到平常 4 小時中位數的一半 → 收斂；其他 → 偏多 / 偏空。另附目前 UTC 時段的歷史盤整率（`config.json` 的 `session_chop_pct`，下表）。

### 4. 新聞催化劑（`--news`，未驗證）

`screener/news_catalyst.py` 抓 Bybit 與 OKX 的官方公告、CoinDesk / The Block / Cointelegraph / Decrypt 的 RSS（有 `CRYPTOPANIC_TOKEN` 環境變數再加 CryptoPanic），把每則新聞對應到幣（`$SOL`、`(SUI)`、`PEPEUSDT`、`news_aliases.json` 的名稱、大寫代號整字；SEC、ETF 這類縮寫與 TRUMP 這類容易混淆的代號另外處理；一次提到 5 個以上幣的行情回顧不算），依關鍵字分類，再依來源層級（官方 1.0、媒體 0.7、聚合 0.4）× 影響（1–3）× 時間衰減（半衰期 12 小時，只看 48 小時內）打分。Binance 的公告沒有正式公開 API，所以不抓。

| 類型 | 方向（一般解讀） | 影響 | 對篩選器的作用 |
|---|---|---|---|
| 下架 | 負 | 3 | 官方公告，或兩家媒體報導 → **剔除**（合約要終止）；只有一家媒體 → 避開 |
| 駭客 / 漏洞 | 負 | 3 | 72 小時內 → 避開 + 提醒 |
| 上線、ETF | 正 | 2 | 24 小時內 → 焦點 |
| 監管 / 訴訟 | 不定 | 2 | 提醒 |
| 代幣解鎖 | 負 | 2 | 提醒 |
| 總經（CPI、FOMC、Fed…） | 不定 | 2 | 沒有對應幣 → 列在「總經 / 全市場」 |
| 升級、合作、空投 / 銷毀、資金流、交易所調整 | — | 1 | 計分 |

標記：**焦點**＝通過門檻 + 24 小時內有影響 ≥ 2 的非負面催化劑，或 2 個以上來源；**避開**＝下架 / 駭客；**有新聞**＝24 小時內有其他新聞；**舊聞**＝24–48 小時。

**催化劑的分數權重是 0**：不改變排名，只做標記、剔除下架合約、寫進紀錄。原因是歷史新聞在這個環境拿不到，無法回測；改用前向驗證（下面「新聞催化劑的前向驗證」），條件已事前登記在協議裡。Bybit / OKX / RSS / CryptoPanic 的介面依官方文件或常見格式實作、用模擬回應測試，**沒有在這個環境實際連線過**（全部被擋）。

## 驗證

### 設計（事前登記）

- 資料：data.binance.vision 上**全部** 924 個 USDT 永續代號（896 個在期間內有資料，含已下架），15 分鐘 K 線，2025-11-01 → 2026-11-16。
- 每天 UTC 00:00 用前 14 天算指標、套門檻、排名；量測**隔天**：盤整率（ER < 0.15 的 4 小時區塊比例，主要結果）、4 小時 ER、4 小時淨移動 %、日振幅。
- 研發期 2025-11-15 → 2026-05-31（198 天）選因子、定權重；保留期 2026-06-01 → 2026-11-15（167 天）。
- 每天合格幣數中位數：研發期 64、保留期 50。
- **協議外修正**：保留期第一次執行後發現股票 / 商品永續漏過了過濾（保留期前 10 名有 14% 是它們），修正過濾後研發期選出的因子不變、保留期重跑一次。兩次結果都公開，判定相同。細節見協議的補記。

## 對日內交易真正有用的（都有數據）

1. **只交易過門檻的加密貨幣**：死幣、極低流動性的幣是盤整的大宗（49% → 37%）；股票 / 商品永續不是加密貨幣，而且週末冷清。這是篩選器最有價值的部分。
2. **挑會動的幣**：盤整的機率大家都一樣，但清單上的幣「動的時候」走得比較遠（每 4 小時 2.03% vs 1.57%）。同樣的手續費（合約每邊約 0.05%）與滑價，換到的空間比較大。代價是停損也要跟著放寬、部位要縮小。
3. **時段**：UTC 12–16（台北 20:00–24:00）兩期都最少盤整；台北中午到下午（UTC 04–08）偏多。
4. **預期大約 1/3 的 4 小時視窗會盤整**，事前看不出來。進場後的處理方式（停損、出場、要不要時間停損）要配合你自己的進場規則回測，這份研究沒有驗證任何出場規則。

## 新聞催化劑的前向驗證

`scan --news --log` 每天把完整結果存進 `~/.intraday-screener/runs/<UTC 日期>/`，排程的 AI 另外寫 `ai_report.json`（焦點 / 避開）。`research.py forward` 對每天最早的一次紀錄，用 Binance 歷史資料庫量測之後 24 小時的盤整率與 4 小時淨移動，比較：全部合格、篩選器前 10、有 24h 內新聞、沒有新聞、程式焦點、AI 焦點、AI 避開。

判定條件（協議「新聞催化劑的前向驗證」）：焦點組至少 60 個交易日；盤整率低於合格平均且 ≥ 55% 的天數成立（HN1 / HA1）、4 小時淨移動 ≥ 合格平均（HN2 / HA2）。兩條都過才可以登記新版本、給催化劑權重，再驗證一次；在那之前權重維持 0。

目前狀態：**0 天**（2026-11-17 開始可以累積）。

## 限制

- 只用 Binance 的資料驗證。Bybit、OKX 的介面依官方文件格式實作、用模擬回應測試（`test_screener.py`），本環境連不到它們的 API，沒有實際連線測試過。
- 歷史模式沒有掛單簿，價差與滑價門檻沒有被驗證，只是執行成本的常識門檻。
- 非加密合約清單是用 Binance 2025-11 → 2026-11 的資料產生的；之後新上的股票合約靠 `underlyingType`（只有 Binance 即時模式）和 14 天備援檢查。其他交易所若有和清單同名的加密貨幣，會被誤排除。
- 盤整的定義是 15 分鐘收盤價、4 小時區塊、ER < 0.15。用其他週期（例如 5 分鐘、1 小時）交易的人，結果可能不同。
- 期間 2025-11 → 2026-11 大部分是熊市；牛市或極端事件期間的表現沒有被測到。
- 決策時點固定在 UTC 00:00；即時模式用「最近 24 小時」滾動切段，概念相同但時點不同。
- 新聞催化劑沒有歷史驗證；新聞與幣的對應是關鍵字規則，會有漏抓與誤配（例如同名的人或公司），AI 層的人工判讀用來補這個缺口。

## 重跑驗證

```bash
SK=skills/freqai-ea-trading/screener
python3 $SK/research.py download --start 2025-11 --end 2026-10 --daily-tail     # 約 140MB 快取在 ~/.cache/intraday-screener
python3 $SK/research.py factors  --from 2025-11-15 --until 2026-05-31
python3 $SK/research.py evaluate --from 2026-06-01 --until 2026-11-15
python3 $SK/research.py intraday --from 2026-06-01 --until 2026-11-15
python3 $SK/research.py gates    --from 2026-06-01 --until 2026-11-15
python3 $SK/research.py forward  --log ~/.intraday-screener/runs                   # 新聞催化劑的前向驗證（累積 60 天後才判定）
python3 $SK/test_screener.py                                                       # 133 項離線測試
```

結果檔：`references/results/screener_{dev,holdout}_{factors,eval,intraday,gates}.json`；保留期第一次執行（含股票合約）是 `screener_holdout_*_run1.json`。
